Both defer and async instruct the browser to download a JavaScript file in the background without blocking the HTML parser. The difference lies entirely in when the script executes and whether the execution order is maintained.

Feature defer async
Download Behavior Asynchronous (non-blocking). Asynchronous (non-blocking).
Execution Timing Waits until HTML parsing is completely finished (just before DOMContentLoaded). Executes immediately once the download completes, pausing HTML parsing to run.
Execution Order Guaranteed to run in the exact order they appear in the HTML document. Unpredictable. Runs as soon as the file is ready, regardless of document order.
DOM Availability Guaranteed (the entire DOM is constructed). Not guaranteed (HTML parsing is likely still underway when the script runs).

When to use defer:

  • The script relies on the DOM being fully loaded (e.g., attaching event listeners to UI elements).
  • The script has dependencies on other scripts (e.g., your app.js needs vendor.js to run first).

When to use async:

  • The script is completely independent and does not interact with the DOM or other scripts (e.g., Google Analytics, tracking pixels, or third-party ad networks).
  • Getting the script running as fast as possible is the only priority, regardless of order.
