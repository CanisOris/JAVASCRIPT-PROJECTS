JavaScript Reference Vault

A visual repository of syntax, patterns, and code snippets.

Error: The generic base object for all built-in error types. It is often used by developers to create and throw custom exceptions.

SyntaxError: Thrown when the JavaScript engine attempts to parse code that violates the language's syntax rules (e.g., a missing bracket, unclosed string, or misspelled keyword).

ReferenceError: Occurs when code attempts to access a variable that does not exist or has not been initialized in the current scope.

TypeError: Triggered when an operation is performed on a value of the wrong type (e.g., trying to call a string as a function, invoking a method that doesn't exist, or accessing a property of null or undefined).

RangeError: Thrown when a numeric value or parameter falls outside of its valid, allowed range (e.g., creating an array with a negative length or passing an invalid radix to Number.toString()).

URIError: Happens when global URI handling functions, such as decodeURIComponent() or encodeURI(), are passed malformed URIs.

AggregateError: Wraps multiple individual errors into a single object. This is most commonly thrown by operations like Promise.any() when all promises passed to an iterable are rejected.

EvalError: Historically used to indicate errors regarding the global eval() function. Modern JavaScript engines no longer throw this error, but it remains in the specification for backward compatibility.
